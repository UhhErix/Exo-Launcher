## 3. Deep Frontier Analysis & Proposals (All 32 Moonshots)

### #1. Predictive Pre-Launch Asset & Shader Cache Prewarm (`lab-asset-prewarm`)
- **Today in Exo:** `ShaderRebuild.cs` and `ShaderPrepare.cs` compile shaders while idle; `LaunchOrchestrator.cs` launches games cold from disk.
- **2026 Frontier:** Microsoft **Advanced Shader Delivery (ASD)** (SODB → PSDB via DirectX Agility SDK, rolling out on Xbox/Steam/Epic for new DX12 titles); Windows `PrefetchVirtualMemory` Win32 API; Valve's Steam Deck Fossilize. Nobody on Windows combines per-game ETW asset I/O recording with pre-launch RAM page-cache warming + driver shader blob warming across all stores.
- **The Exo Moonshot:** While a game runs, a lightweight ETW `FileIo` trace (zero hooks, anti-cheat safe) records the exact `(path, offset, length)` ranges read during the first 60 seconds of cold startup and initial map loads (`.pak`, `.ucas`, `.utoc`, DLLs, driver DXCache/GLCache/D3DSCache files), compacting them into a tiny per-game hot-extent manifest (capped to safe RAM budget, e.g., ≤25% of free RAM on ≥32 GB PCs). When the player hovers a game in Library, opens its Game Page, or hits Play (or on idle schedule for top 2 Continue games), Exo asynchronously warms those exact extents into Windows' Standby Page Cache via `CreateFileMapping` + `PrefetchVirtualMemory`, and surfaces Windows 11 ASD status alongside `Exo Shaders` priority hotlists.
- **Beats & Target:** Beats cold NVMe/SATA loads, Windows SysMain (disabled by most gamers), and Steam Shader Pre-Caching (Vulkan-only). Target: **-30–55% cold boot & first-map load time** and **-60% first-5-minute asset-streaming micro-stutters** on ≥32 GB RAM rigs.
- **Evidence:** `PrefetchVirtualMemory` (`kernel32.dll`, Win8+) issues large coalesced async disk I/O directly into the OS page cache with zero process injection; ETW `Microsoft-Windows-Kernel-File` (`Read` opcode) exposes exact file offsets per PID; `fsutil` / DXGI / Agility SDK exposes ASD state.
- **Risk:** Anti-cheat: **None** (pure read-only file mapping of game files on disk + passive ETW). Stability: **Low** (must strictly cap prefetch budget so `StandbyPurger` never triggers and free RAM stays >4 GB). Legal: **None**.
- **Effort / Release:** **S** · **3.x**
- **48-Hour Kill-or-Prove Experiment:** Record ETW `FileIo` reads for the first 45 s of 3 heavy cold-boot games (e.g., Cyberpunk 2077, UE5 title, CoD/Valorant on cold cache cleared via `EmptyStandbyList`), measure 5 cold boots vs 5 `PrefetchVirtualMemory`-warmed boots; **prove** if median time-to-menu drops ≥25% and first-minute 0.1% lows improve ≥15%.

### #2. OLED Anti-Flicker VRR Governor & Hardware MHC2 Color Pipeline (`lab-oled-vrr-mhc2`)
- **Today in Exo:** `GameHdr.cs` toggles Windows HDR per game; `SdrInHdr.cs` patches SDR-in-HDR gamma 2.2; `MonitorDdc.cs` adjusts brightness. `perf-display` covers laptop eDP HDR.
- **2026 Frontier:** `MHC2Gen` (`dantmnf/MHC2`) generates Windows 11 MHC2 ICC profiles with hardware GPU LUT transforms (0% shader cost) for sRGB gamut clamping + true 2.2 gamma inside HDR; `novideo_srgb` (NVIDIA-only, breaks in HDR); manual RTSS capping to stop OLED VRR brightness pulsing near LFC boundaries.
- **The Exo Moonshot:** (1) **Zero-Cost Hardware MHC2 Profile Generator**: reads monitor EDID chromaticity primaries + Windows HDR Calibration min/max nits (plus optional RTINGS/community database) and generates signed-format Windows 11 **MHC2** ICC profiles applied via `WcsAssociateColorProfileWithDevice` — delivering hardware-LUT sRGB gamut clamping (eliminating oversaturated skin tones on QD-OLED/WOLED), true gamma 2.2 SDR-in-HDR, and black-level floor correction across **NVIDIA, AMD, and Intel at 0.00% GPU overhead**. (2) **OLED VRR Flicker Governor**: watches `PresentTrace` frame-time variance and LFC floor crossings (<48–55 Hz); detects flicker-prone loading/menu/CPU-dip regimes and applies smooth driver-cap stabilization + optional `EnableDwmVrr=0` desktop guard + DDC/CI idle dimming to protect OLED longevity.
- **Beats & Target:** Beats `novideo_srgb`, DisplayCAL, Windows HDR Calibration app, and monitor OSD hacks. Target: **-70% LFC boundary crossings/min** during erratic frame-time segments, **ΔE < 1.5 sRGB gamut clamp in HDR** at **0.00% GPU shader cost**.
- **Evidence:** Windows 11 Color Management API (`mscms.dll` / `ColorProfileAddDisplayAssociation`) natively loads MHC2 `MHC2` tag 3×3 matrix + 1D LUT into DWM/GPU display hardware on WDDM 3.0+ across all 3 vendors; `dantmnf/MHC2` is MIT/open-source reference.
- **Risk:** Anti-cheat: **None** (OS color profile + driver cap). Stability: **Low** (atomic profile backup/restore via `WcsDisassociateColorProfileFromDevice`). Legal: **None**.
- **Effort / Release:** **S** · **3.x**
- **48-Hour Kill-or-Prove Experiment:** Generate an MHC2 ICC profile from this PC's EDID primaries + gamma 2.2 LUT, associate it in HDR mode, verify via Windows ACM / screenshot pixel delta & PresentTrace that GPU overhead is 0.00% and sRGB gamut clamps cleanly without breaking HDR peak luminance; test LFC crossing counter on a synthetic fluctuating framerate workload.

### #3. Predictive Standby & VRAM-Pressure Shield + Opt-In Large Pages (`lab-memory-shield`)
- **Today in Exo:** `StandbyPurger.cs` silently fails with `_denied=true` when unelevated (only fixed reactively in `perf-ai-bugs`); no VRAM pre-eviction of background browsers/Electron apps; zero Large Pages (`SeLockMemoryPrivilege`).
