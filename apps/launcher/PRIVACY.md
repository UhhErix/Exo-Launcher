# Exo Launcher privacy statement

**Exo Launcher is local-first: your library, installs, updates and game launches work offline, and there are no ads. An Exo account (email and password) is required; it syncs your choices (settings, wishlist, Riot ID, music service, custom covers) and your playtime between your PCs. Exo sends anonymous usage data and crash reports to its own service so the team can fix and improve it; there is no switch for this from 3.26.0, and what is sent is listed in App data and crash reports below.**

Once this PC has signed in to an Exo account, your library, installs, updates, game launches and settings work offline. The one thing Exo waits for is that account: a signed-out PC is asked to create or sign in to one before Exo opens, and if Exo's account service can't be reached, **Continue without an account** lets Exo work on this PC until the service answers (see **Exo account**).

## App data and crash reports

From 3.26.0 every install of Exo Launcher sends the app data and crash reports described here. Versions 3.25.0 and earlier asked first and had two switches in **Settings > Privacy**; those switches are gone, and a choice of **Don't share** made in an earlier version no longer applies. The data is anonymous: it is tied to a random install ID, not to you or your Exo account. **Settings > Privacy** still shows what was sent and deletes what Exo's service holds.

Exo sends a short record of these events, so the team can see how long things take and where they fail:

- **App started**: how long startup took, in milliseconds.
- **App closed**: how long the session lasted, and whether it closed cleanly.
- **Game launched**: that you started a game from Exo. No game name.
- **Room opened**: which room you opened (home, library, store, Discord, music, PC, devices or settings).
- **Library loaded**: how long the first library read took, how many games you have as a size range (0-49, 50-199, 200-999 or 1000+), and how many stores.
- **Store sync failed**: which store (GOG, for now) and the kind of error.
- **Update result**: the version Exo updated from and to, whether it worked, and the kind of error when it did not.
- **Download finished**: for a store tool Exo fetches for itself, its kind, a size range, and that it arrived.
- **Memory**: Exo's memory use in size ranges, every 10 minutes, in about one session in ten.
- **Dropped events**: how many events were lost because the offline queue was full.

Each event also carries Exo's version and channel, your install ID, and a random session ID for this run. Each value is checked against a fixed list on your PC first; a value that looks like a path, URL, name or ID is dropped, not sent.

| Collected | Never collected |
| --- | --- |
| The events above, with Exo's version and channel, your install ID and a session ID | Names, email addresses, account IDs and anything in your Exo account |
| Room names, the game-launched action, and timings, counts and sizes, as numbers or size ranges | Game names or folders, your library's contents, watched titles, media file names |
| The store and error kind of a failed store sync; the versions and error kind of an update | File paths, URLs, search terms, browsing history |
| Dropped-event counts | Discord messages, contacts and voice; your store or Riot sign-ins; hardware serials, MAC addresses, Windows SIDs and any fingerprint of your PC |

A **crash report** holds Exo's version, your Windows build (numbers only), the error's type, a scrubbed log excerpt of at most 8 KB, and your install ID. The install ID is what lets **Delete my data** remove it. Paths, URLs, host and machine names, user names, IP addresses, emails, IDs, tokens, and the names of your games and installed programs are taken out on your PC first.

**How it's sent.** Events wait on this PC in a queue and go to `reports.getexo.app`, Exo's own Cloudflare Worker: one batch at most every five minutes, in a request of up to 64 KB. Offline, up to 1 MB waits on this PC, oldest first. A live crash report is sent when it happens. If Exo's service refuses it under load, fails or doesn't answer, or this PC is offline, the report is kept on this PC and sent at a later start; an unhandled crash is saved the same way. At most five reports are kept, the oldest going first. One is sent at each start, and it is deleted once it is sent, once a daily limit refuses it, or after it has failed at three starts. Sending runs in the background and never slows Exo or delays its exit. Exo's service limits how often each install, and each IP address, may send in a minute; Cloudflare keeps those counts for the minute and Exo stores neither.

**Your install ID.** A random ID, one per app on this PC. It isn't tied to your Exo account, your Windows account or your hardware, and Exo doesn't fingerprint your PC. It is replaced every 90 days and whenever you choose **Delete my data**.

**Settings > Privacy.** **View what's sent** shows the last 20 payloads, exactly as they left, including crash reports. **Delete my data** asks Exo's server to delete everything stored under your install ID, then makes a new one.

**Keeping it.** Raw events are kept 90 days and crash reports 30 days. After that only totals remain, with no install ID. For every stored crash report the service also adds one to a count by app, version, error type and UTC day, kept 90 days with no install ID, and files the error for the team as an issue in a **private** GitHub repository of Exo's own (UhhErix/Exo-Reports, which only the team can see): one issue per error, opened by its first report with the app, version, Windows build, error type and that report's scrubbed log excerpt, then kept up to date with how many times it was seen, in which versions and on which days. Workers AI on Exo's Cloudflare account reads the scrubbed log of an error's first report to write a short note on the likely cause into that issue. The issues are not covered by the 30 days or by **Delete my data**; the team closes them when the error is fixed and deletes one on request. Until that repository is connected, the service tells the team as it did before, by email and in a private Discord channel of the team's own: the first, 10th, 100th and 1000th report of an error in a version, with the app, version, Windows build, error type and the last 1,500 characters of the scrubbed log, at most 50 a UTC day, and a daily summary of the counts; those messages are not covered by the 30 days or by **Delete my data** either. Reports and counts are stored on Cloudflare, on Exo's own account. Exo uses no third-party analytics SDK, and never sells or shares the data.

## What stays on this PC

Exo keeps its data in `%LocalAppData%\ExoLauncher`. This includes:

- settings (`settings.json`, which also holds your Library folders), the library cache, playtime Exo recorded, the Xbox hours Exo read before Xbox sign-in was retired (kept as the Xbox seed in `playtime.json`: game titles and minutes only; the old `reported-hours.json` is removed once they are moved there), window position, cover art and thumbnail caches, achievement cache and icons (`achievement-art`), and upscaler backups;
- for Best settings' frame generation, the games Exo put a mod in (`frame-gen\games.json`), what it learned in each game (`frame-gen\learned.json`: whether DLSSG SM86's first session failed there, how often Exo put back its files after they went, and why a game is kept off, with the name of the file another mod put over Exo's), and Exo's copies of the mods' releases. In the game's own folder Exo writes the mod beside the game's program (DLSSG SM86: `version.dll`, `dlssg_sm86.ini` and a `dlssg_sm86` folder; OptiScaler: one DLL, `OptiScaler.ini` and an `OptiScaler` folder) and a record of what it wrote (`exo-frame-gen.json`); the mod writes its own logs there as it runs, which Exo reads after a session to say whether frame generation ran. With OptiScaler on an NVIDIA card whose driver caps the frame rate, the game's own NVIDIA profile turns that cap off and OptiScaler's settings take it. Turning it off removes all of it that is still Exo's and puts the profile's value back; a file another mod put over Exo's stays, and Exo's record keeps that one file's name until it is gone;
- what Exo keeps in place on this PC (`keep.json`): each value Optimize wrote into a game's settings file with what was there before, what Exo has seen of it since, your graphics driver's version, and what Game Mode, Game Bar and a store app's quiet settings held before Exo changed them, so each can be put back exactly. It is in your backup and is never synced or sent;
- the start-up items Exo keeps off and when one came back (`startup-guard.json`), and which graphics driver your shaders were last compiled again for with the games still waiting (`shader-rebuild.json`). Neither is synced or sent;
- each game's frame times (`session-recorder.json`): while a game other than Riot's runs, Windows' own event tracing tells Exo when the game presents a frame, as for the FPS counter, and Exo keeps a summary per session (how long, the average, the slowest frames, the stalls) with a short hash of the settings in place. Nothing goes in the game, and it is never sent anywhere. It records only when your account already has the tracing permission described next;
- for the FPS counter, if you turn it on: nothing is saved but your choices. While a game runs and is in front, Windows' own event tracing tells Exo when that game presents a frame. Nothing goes in the game, and Exo doesn't open it for this. Anything you add to it (GPU, CPU, memory) is read from Windows while it shows and kept nowhere. If Windows doesn't already let Exo trace, turning it on asks through Windows' own prompt to give your account permission for Exo's one trace session and the three graphics event sources it reads, and if that isn't enough, to add your account to the Performance Log Users group. Those stay after you turn it off. You can remove the group in Computer Management › Local Users and Groups, and the permission is the values named `7e4c6a5e-93b1-4e3c-8f3a-2b1d6c0f5a91`, `ca11c036-0102-4a2d-a6ad-f03cfed5d3c9`, `783aca0a-790e-4d7f-8451-aa850511c6b9` and `802ec45a-1e99-4b83-9920-87c98277ba9d` under `HKLM\SYSTEM\CurrentControlSet\Control\WMI\Security`;
- copies of custom game covers you choose. With an Exo account, your cover choice syncs, and so does the picture when it is small enough for one item (about 48 KB); a bigger one stays on this PC;
- your Store wishlist (`store/wishlist-v2.json`) and the last sale price Exo told you about, the Store's saved pages (`store/home-v5.json`, Steam's public facts about the games it showed in `store/items-v2.json`, tag names in `store/tags-v1.json`), and your Exo Mouse profiles and presets (`mouse/profiles.json`, `mouse/presets.json`);
- the parts Exo fetches when it installs: the store tools (Legendary, gogdl, Nile) and their data, and NVIDIA's TitaNet model for Only My Voice (in `tools`, `voice` and `models`; uninstalling Exo removes them), plus the browser data from the Epic and GOG sign-in windows, the Riot Client sign-in files you saved for switching accounts (`riot-accounts`, kept on this PC only), and, if you sign in to Steam in Exo, that sign-in's tokens (`steam-account.bin`, encrypted for your Windows account);
- Exo Shaders, the shader engine behind PC > Graphics > Shaders, keeps its compile records, recordings and settings in `%LOCALAPPDATA%\SCSKiller` (the same folder SCSKiller uses). Exo passes it your installed games' names and folders so it can find their shaders; nothing leaves your PC (see **Exo Shaders** under **Other network requests** for the files it may download). It runs when you press Refresh or Compile, and by itself after a graphics driver update to compile again the games it had compiled (only while nobody is using the PC), and Exo keeps in `shaders-engine.json` what it saw last time (your graphics driver's version, short hashes of your installed games and their programs, and when it ran) so it starts only when something changed;
- Exo Capture, the add-on behind the Capture button, saves the instant replays, recordings and snips you ask for in your captures folder (`Videos\Exo Captures` unless you choose another), and keeps its settings, thumbnails and which game each capture belongs to in `capture` under Exo's data folder. It captures the game's window or the screen through Windows; only when Windows gets no picture from a game (exclusive full screen) does it load OBS Studio's game capture hook into that game to copy its frames, and only into a game Exo's own check found to have no anti-cheat and could read whole (see **Games and anti-cheat**), never into a Riot game, and never while Easy Anti-Cheat, BattlEye, FACEIT or ESEA runs; otherwise it captures from the screen only. Every replay and recording has the mix of the game (with no game, the apps playing on this PC) and your default microphone, and each of the two on a track of its own. A Discord call's voices, in Exo or in the Discord app, are left out: on no track and not in the mix. With no game, so are apps that play a call or a microphone again (Discord, mixers such as Voicemeeter, Sonar or Wave Link, voice changers, Teams and Zoom). Capture settings › Record the call's voices (off unless you turn it on) puts the call in, on a track of its own and in the mix; then, while instant replay or a recording runs during a call in Exo's Discord room, Exo flags you in the call as having clips on, as Discord's own clips do, so everyone in it is told. When someone else in your call has clips on, Exo's voice bar shows a red dot. Mute a track in your player or editor to leave it out of a file. While instant replay or a recording runs, your microphone is in use and Windows shows its microphone indicator. Instant replay holds the last minutes in memory, by default only while a game is running, and writes nothing until you save. Captures never leave your PC by themselves: Send to Discord copies the file and opens the Discord room for you to paste it into a chat. A storage limit or age you set sends the oldest captures to the Recycle Bin; favorites are always kept. A capture you delete goes to the Recycle Bin too;
- Exo Notes (Captures › Notes) keeps your notes as plain text and Markdown files in `Documents\Exo Notes` (your user folder's `Exo Notes` when Documents is kept in OneDrive), and in `notes` under Exo's data folder which notes are open, their pins and the game each was written in, and the edits of a file opened from elsewhere until you save it. A word you right-click is checked by Windows' own spell checker on this PC; Add to dictionary puts it in Windows' word list. Nothing in a note is sent anywhere. Exo adds itself to Windows' Open with and Default apps for .txt, .md and .log files (for your account only) only when you choose Open text files with Exo; Windows keeps which app opens them, and Stop opening text files with Exo, or uninstalling Exo, takes it out.
- Backups (Settings › General › Backups) write one file a day, `exo-launcher-backup-<day>-<PC id>.json`, to `Documents\Exo\Backups\Launcher`. It holds everything you chose in Exo: your settings (with the choices made in Discord, Devices, Shaders and the PC room), your Library folders and their pictures, custom covers, the games you added yourself, your wishlist, your playtime, the Riot ledger and your Riot ID, the Xbox hours kept from before, your notes, the window's place, Exo Mouse profiles and presets, what each controller remembers and its per-game settings, your Exo EQ (headphones, sounds, per-game sounds and Night Shift), each game's window mode, what Optimize changed in your games' files and the files as they were (so Put back still works), which games have frame generation on, what you removed from start-up and from the apps a driver installs, and the connected-app file, which holds your music service and the answers you gave for microphone, camera, clipboard and notifications. Pictures are kept once beside the backups, named by the PC that wrote them and by their contents, for all the days that use them; a PC removes only its own pictures, and only ones no backup names. What a backup leaves out of its text: a folder path under your user folder becomes a mark that is filled in again for whoever restores, and a start-up task's Windows user too (a task that ran as Windows itself is not restored); a start-up shortcut is kept as what it starts (its target, arguments, folder, icon and description), not as the shortcut file. What it keeps as written: a path outside your user folder, a path written in Windows' old short form (such as `C:\Users\JOSEMA~1`), the launch options you typed for a game, the words in a shortcut's arguments or description, and the game files Optimize found (the game's own files as they were, for Put back). A backup carries a salted one-way mark of the PC it was made on, different in every backup, so a restore on another PC leaves out what Optimize and frame generation changed in that PC's games. When a backup stops (too large to restore, a file that cannot be read, a backup that does not read back, Documents not writable), Settings › Backups says so in one sentence and Exo says it once, when it happens, and the last good backup is kept. A backup is written when Exo starts (only if none was written that day), when the last game running closes, and when Exo closes (unless one was written in the last ten minutes). A backup that would be too large to restore is not written; the game files kept for Put back are left out first. Export and Import use one file that holds its pictures, and the newest 30 days (this PC's) are kept. No sign-in, token or account session is ever in a backup; the file is not sent anywhere.
- the browser profile used for YouTube Music and Apple Music;
- your install ID and the queue of events waiting to be sent (`telemetry\`), and the last payloads for **View what's sent** (`telemetry\sent.jsonl`), and crash reports waiting to be sent (`pending-reports`: at most five, each the scrubbed report and a count of tries, with no install ID);
- logs (see **Logs** below).

PC > Apps keeps on this PC what it needs to clear up after a program and to put that back: every program it has seen with its folder and when each last ran (`apps-seen.json`, read from Windows' own records of what ran), and what it removed (`removals.json`, and the registry entries it saved first in `cleanup`). Nothing of it leaves your PC.

To find your games, Exo reads local folders, store manifests, registry keys and data saved by store clients on this PC. For hours, it also reads GOG Galaxy 2.0's database (`galaxy-2.0.db`, read-only) for the time Galaxy holds for games on the other platforms you connected to it. Exo does not upload your library, install folders, launch settings, playtime or achievements. Some services see a game title or store id when Exo looks up artwork or hours for it; they are listed under **Other network requests**.

To free memory, Exo reads the process list on this PC (names, parent processes, and the command line of a Battle.net process to tell its renderers apart) to find the browser helpers of Steam, the Epic Games Launcher, the EA app, Ubisoft Connect, GOG Galaxy and Battle.net, and lowers their memory use while they are hidden. It reads nothing inside them, keeps nothing and sends nothing.

**Keys and sign-ins stay local.** Your Riot ID is public (Name#TAG), so Exo keeps it as a plain file (`riot-id.txt`) that your backups and your Exo account carry, and sends it only to tracker.gg (see **Other network requests**). Exo no longer asks for or reads keys: a copy saved by an older version (Steam Web API, itch.io, SteamGridDB, OpenXBL, IGDB) is deleted when Exo starts.

Store sign-ins stay with the official tools:

- Epic sign-in goes to Legendary.
- GOG sign-in goes to gogdl.
- Amazon sign-in goes to Nile.

Exo opens the store's own sign-in page, passes the result to that tool, and does not keep its own copy of the token.

**Steam sign-in (optional).** In Settings > Library you can also sign in to Steam inside Exo, by scanning a QR code with Steam's phone app (the default) or with your account name and password; Steam Guard is answered in Exo. A password is typed into Exo's own form, encrypted for Steam on this PC and sent only to Steam; Exo never keeps or logs it. What Steam returns, the account's name, SteamID and sign-in tokens, Exo keeps on this PC, encrypted for your Windows account (`steam-account.bin`); it is never in a backup or your Exo account. Signing in tells Steam this PC's name ("Exo on <PC name>") and a machine id that is a hash of the PC's and Windows user's names. With the tokens Exo reads from Steam's own service the games your account owns, your Steam Family's shared games and a game's achievements (see **Other network requests**); no web API key is used. **Sign out** there revokes the sign-in with Steam and deletes the file. Exo drives Steam in ways Valve's terms do not cover, as Exo's Discord room does with Discord; where it can, Exo falls back to Steam's own client.

**Accounts in Settings > Library.** To show who each store is signed in as, Exo reads the display names in Steam's `config\loginusers.vdf`, Legendary's `user.json`, Nile's `user.json`, and the Epic Games Launcher's account id in the registry (to tell whether it uses a different account). Only display names reach the page; account names, ids and tokens are never logged. Switch account on Steam does what Steam's own account picker does: it closes Steam, marks that account as the one to sign in to in `loginusers.vdf` and the registry (`AutoLoginUser`, `RememberPassword`), and starts Steam again. Switching accounts needs no password and never touches `config.vdf`. Epic accounts you add for their hours each get their own Legendary folder in `%LocalAppData%\ExoLauncher\epic-accounts`, and the last Epic playtime of each account signed in on this PC is kept in `epic-playtime.json` under a one-way tag. Exo adds up the hours each Steam account on this PC and each of those Epic accounts recorded; nothing is sent anywhere new.

**Store settings Exo changes.** For each installed Steam game Exo turns the Steam overlay on where the game needs it (purchases through Steam, playing online with friends, Remote Play Together, Steam Input) and off elsewhere, sets Steam Input from the game's controller support, and, while **Keep store apps quiet** is on in Settings › Game stores, keeps Steam's and Epic's own pop-ups and sounds off, recording what each setting held so that turning it off puts it back. Exo writes these switches into each Steam account's `localconfig.vdf` and `sharedconfig.vdf` and into Epic's own settings, on this PC, while those apps are closed; nothing else in those files changes, and a switch you change in Steam afterwards stays yours. Exo never closes a running Steam to write them, and leaves cloud saves and automatic updates as you set them. When Steam asks for a game's EULA, Steam shows the agreement for you to accept or decline; Exo never accepts it or writes accepted licence versions into Steam's files. Exo can continue Steam's default launch choice, but never an agreement or a purchase.

**Games and anti-cheat.** Before Exo puts anything into a game, starts it with your launch options or as administrator, or changes its settings, it checks the game for anti-cheat on this PC, and sends nothing for it. It looks at the game's store, at the folders, files and launcher stubs of the anti-cheats it knows (Easy Anti-Cheat, BattlEye, Vanguard, Ricochet, nProtect, XIGNCODE, FACEIT, PunkBuster, EA's and others) anywhere in the game's folder, at Windows services whose program sits there, and for a Steam game at Steam's own record on this PC of its anti-cheat category and Valve Anti-Cheat; a list of known titles always counts too. With none found, Exo does what you turned on. With one found, or when Steam can't say whether a Steam game uses Valve Anti-Cheat, Exo changes only what the game itself offers (its own settings file, launch options without anything that switches the anti-cheat off or loads a file, deleting what the game makes again) and, only after you allow it for that game, swaps the vendor's own signed DLSS, FSR or XeSS file for a newer one; it places no file, mod, frame generation, shader recorder or capture hook, and does not start the game as administrator. A game Exo can't read gets nothing at all. Exo never changes Riot's games or Vanguard's driver and service. It may hide and close the Riot Client's windows, ask it to quit, switch its signed-in account, and, if you choose, take Vanguard's tray icon out of start-up.

**When Steam's servers are down.** While Steam runs, Exo reads two of Steam's own logs on this PC every 15 seconds (`logs\connection_log.txt` and `logs\steamui_login.txt`: whether Steam's sign-in was answered, and Steam's own internet check) to tell you once when Steam can't reach its servers; nothing is sent anywhere and nothing from them is kept. If you choose Play offline, Exo closes Steam (never while a Steam game runs), turns on Steam's own offline mode for the account Steam signs in as (`WantsOfflineMode` and `SkipOfflineModeWarning` in `config\loginusers.vdf`, what Steam's Go Offline writes), and starts Steam again. It first keeps a copy of that file (`steam-offline-loginusers.vdf`) and the two values it had (`steam-offline.json`) in Exo's data folder, puts exactly those values back when Steam's servers answer again (or after you go online in Steam), and then deletes both. Nothing else in the file changes, and no password or token is read.

**Gifts.** To show gifts waiting for you in the Library, Exo opens Steam's and Epic's own gifts pages in a hidden browser with its own profile (`gifts-webview` in Exo's data folder) when you open the Library (at most every half hour) or refresh it, and every half hour while Exo is in front and you're not playing, and reads them; Accept and Decline make the same calls those pages make. Steam's website needs one sign-in there, on Steam's own page (Settings > Game stores > Steam gifts); it stays in that profile until you sign out there. Without Exo's own Steam sign-in, that page also gives the Library the token Steam's store hands its signed-in page (`pointssummary/ajaxgetasyncconfig`), so your Steam Family's shared games show even before Steam has them on this PC (see **Other network requests**); the token stays in memory. Epic's store page is signed in with a one-time code from Exo's Epic sign-in. Gift names, senders and messages are shown, never saved, logged or sent anywhere else.

## Exo account

Exo Launcher uses an Exo account: an email address and a password (Exo's other apps don't use it yet). The account is required. Setup asks for it as the first step after Welcome, and while this PC is signed out Exo opens on its account screen at every start, with no way past it but creating an account or signing in. The one exception is Exo's account service being out of reach: **Continue without an account** lets that run through, and the next start asks again. A recovery code that was shown and not yet typed back keeps the screen up too. **What the account service holds:** a keyed digest of your email address (the address itself is never stored; the service reads it only while a request carries it), a keyed digest of your recovery code (the code itself is shown once and never stored), your password as a hash, the devices signed in to the account (a random device id per PC, when each first signed in and was last used, when the account was made, and SHA-256 hashes of the session and device tokens; a PC unused for 400 days is signed out and leaves the list), and your synced items: Launcher settings (the preferences, including which games you hid, not paths, window positions, GPU, display or Discord voice settings; with them Discord's look, text size and streamer mode, Discord's Performance mode, the Shaders order, and whether your Go Live preview and the call's chat show), your playtime entries, one per play session, the Xbox hours kept from before, the Riot ledger's lines, your custom cover choices and the pictures small enough for one item, your wishlist (one item per game), your Riot ID and your music service. Choices about this PC's hardware stay on it and only in its backups: the driver type (Game Ready or Studio), the headphones you wear, Go Live's quality and the camera for Discord. Each item's value is sealed with AES-256-GCM before it is stored; its type and name are not, and the service sees how many items an account has and when each was written. A wish's name is random; a cover picture's name is a hash of the picture; a cover choice's and an Xbox hours' name is the game's store id, or for a game you added from a folder, that folder's name and a short hash of its path. Each password or recovery-code try also keeps, for at least 15 minutes (removed at a later try), a count under keyed digests of the email and of the IP address (an IPv6 address as its /56), and wrong tries a count under the email digest for an hour; Cloudflare's rate limiter counts password requests per IP address (an IPv6 address as its /56). No IP address is stored and the service keeps no logs. **What it never sees:** your Riot sign-in files, store sign-ins, Discord data, voice data, logs or the files in your library. In Settings > Account you can see the devices signed in, remove another PC's sign-in, change the password (which signs out the other PCs), make a new recovery code, export everything as a plain JSON file, sign out, and delete the account. Deleting it removes the account and its items from the service and keeps the data on this PC.

**On this PC.** The session token, this PC's device token, your account id and the email you typed are encrypted with Windows (DPAPI) for your Windows user and stored in `%LocalAppData%\ExoLauncher\account-session.bin`. They are never in `settings.json`, logs, crash reports or the daily backups. Your account id is also kept in plain text in `account-sync.json`, and this PC's random device id in `device-id.txt`, on this PC only.

Exo 3.3 and 3.4 had an older optional account on a service that has been shut down; its saved session file is removed on start (below).

**On this PC.** The first time Exo 3.4 or later starts, it deletes what an earlier version saved for the account, in `%LocalAppData%\ExoLauncher` and `%AppData%\ExoLauncher`:

- `auth.bin`, the session token, encrypted with Windows (DPAPI), that kept you signed in, together with the account id, handle and email it held, plus any unfinished copy (`auth.bin.tmp`);
- the `online-cache` folder of saved account responses;
- `device-id`, the per-PC id very old versions sent with a library activity summary.

This is a local cleanup only: Exo does not sign out with the service or send it anything. It runs again on every start, so a copy restored from a backup is removed too. Exo writes one line to its log when it removes a saved sign-in.

## Connected apps

Exo's Discord room (its own client) and Music room talk to those services for you, with your own sign-in. Each service keeps its own data and privacy policy. What Exo reads from them (your messages, your library, what you played) is shown to you and not stored, logged or sent anywhere else.

### Discord

- **Exo's own Discord client.** The Discord room is Exo's own client; Exo does not run, install or change the Discord desktop app. You sign in by scanning a QR code with Discord's phone app, so Exo never sees your password. Exo keeps the sign-in on this PC, encrypted for your Windows account (`discord-client.bin` in Exo's data folder), and sends it only to Discord. Messages are shown, never saved or logged, and only channels your roles let you see are shown. An invite link you click is sent to Discord to join that server. A capture you share from Play › Clips is read from your captures folder, up to 25 MB, and sent to Discord as an attachment in the conversation you pick, only after you press Share, choose the conversation and press Send; it is kept in memory for that and nowhere else. Mentions and DMs show as Windows notifications with the message's text, as Discord's app does. A link in a message, a note or the picture viewer is checked for a look-alike of a well-known brand's address (disc0rd, discord-nitro-gift) by its spelling alone, on this PC, with nothing looked up or sent; one that imitates a brand asks before it opens. Discord's terms do not allow third-party clients; that risk comes with signing in.

### Spotify

Spotify plays in its own web player (open.spotify.com), hidden behind Exo on Exo's own web profile, where you sign in on Spotify's own page. Exo never starts or installs the Spotify desktop app, and turns off its start with Windows once. A running Spotify app keeps Exo's player from loading, so whenever Exo's Spotify engine opens it closes the app (first a normal close of its windows, then it ends what is still running after three seconds) and writes that to its log. While you are in a Discord call, Exo also reads the song that plays from Windows' media controls, for the song your call's Exo apps see.

**Recording** is off until you turn it on, on the Shaders page: it puts a small `d3d12.dll` in each game's folder that records which pipelines the game creates, stays on this PC, and refuses a game with anti-cheat and a game whose anti-cheat Exo can't check.

**Prepare** on the Shaders page starts an Unreal game when you press it, or by itself while nobody is using the PC (a switch on that page turns that off), watches the size of your graphics driver's shader cache and the game's processor use, and closes the game when both go quiet. **Exo's Music room for Spotify** draws Spotify's pages itself. ## Exo's relay

Exo's one server piece. It passes sealed messages between Exo apps for two things, so that Discord is told neither: your song inside a Discord call, and what you're playing, for friends who use Exo. Discord's own **Share my activity** has nothing to do with it. **Who runs it:** Exo Launcher's developer, on Cloudflare's Workers platform, which carries the connection.

### In a call

In a Discord call that is end-to-end encrypted (Discord's DAVE), the Exo apps in the call show each other what their Music room plays, so you can listen along with someone in your call.

- **What is sent:** your song in Exo's Music room (its title, artists, length, where it is, whether it plays, the service and that service's id for it), or that nothing plays; and your Discord user id, so the others know it's yours. All of it is sealed with a key made from the call's own end-to-end encryption, which only the people in that call have. Discord never gets it, and the relay can't read it.
- **What the relay sees:** your PC's IP address, a random name for the call that changes whenever someone joins or leaves, how many Exo apps share it, and when and how big each sealed message is (rounded up to one of four sizes). It never sees who you are, which call, or what plays.
- **What it keeps:** each connection's last sealed message, in memory, to hand to whoever joins the call after you; it goes when you leave. Nothing is written to disk, and nothing is logged.
- **When:** only while you're in an end-to-end encrypted call in Exo's Discord room. Leaving clears your song for everyone in the call. In a call that isn't end-to-end encrypted, nothing is sent.

### Between friends

Friends who use Exo see the game you opened from Exo, and Discord and its apps don't. Since 3.26.0 this is part of how Exo's Discord room works, not a setting: there is no switch for it. While you're Invisible, no key is put in your presence, no connection is made, and nothing is sent or heard. To keep a game from being named, hide it from your Library.

- **What is sent:** while a game you opened from Exo runs, its title and the time you started it; otherwise, that nothing runs. Never a game Exo didn't open, one you hid from your Library or one you added yourself, and nothing at all while you're Invisible. It goes only to actual Discord friends who show a key and are online (not server members, friend requests or people you ignored), to 16 of them at most at a time, the ones you last messaged first. It is sealed with a key only you and that friend can work out. Discord never gets it, and the relay can't read it.
- **What Discord gets:** your friend link's public key, 44 characters, as a field of your custom status activity in your presence (on your real custom status if you have one, which stays as it is). Discord's apps don't show it, and no game or Discord sign-in goes with it. Anyone who can read your raw presence through their own software could see the key, and tell from it that you use Exo with this on.
- **What the relay sees:** your PC's IP address, a random name for each pair of friends, which stays the same from one day to the next, when each side is connected, and when each sealed message is sent; every message is the same size. So the relay and Cloudflare could tell that the same two IP addresses keep sharing a name. They never see who either of you is on Discord, or what you play.
- **What it keeps:** each connection's last sealed message, in memory, for the friend who connects after you; it goes when you disconnect. Nothing is written to disk, and nothing is logged.
- **When:** only while Exo is open and connected to Discord, and a friend with a key is online. With no friend on Exo online, no connection is made.
- **On this PC:** your friend link's private key, encrypted for your Windows account (`friend-link-<your Discord id>.bin` in Exo's data folder); it never leaves this PC, and Sign out deletes it.

On the same link, and also without a switch since 3.26.0, friends who use Exo see under your name that a game is installing (how far, in steps of ten), that Exo is building its shaders, or that it is ready (said for 30 minutes, or until you start it). Only a game Exo may name is ever said, never one you hid or added yourself, to the same friends, sealed the same way and kept the same way (in memory, for the friend who connects after you). It is told only by Exo's own install and shader events; nothing looks at a game's process, window or files. Discord never gets it.

## Logs

Exo writes a diagnostic log to `%LocalAppData%\ExoLauncher\logs\app.log`. It holds up to about 2 MB, plus one older file. The log can include:

- game titles and folder names;
- app and store tool messages;
- errors from the app's interface;
- crash details.

Before writing, Exo removes things that look like tokens, passwords, keys, account or store ids, and email addresses. **The log stays on your PC.** Exo never uploads the file itself. A crash report carries only the scrubbed end of the log (see **App data and crash reports**). **Open logs**, offered when part of Exo stops, only opens the folder. If you share a log for support, check it first.

## What Exo Launcher does not do

- No ads, and no advertising or third-party analytics SDK. Usage data and crash reports go only to Exo's own service (see **App data and crash reports**), anonymous and scrubbed first.
- No online dependency for your library or game actions. The library works offline; the account syncs only what is listed under **Exo account**.
- No library activity sent anywhere except your own Exo account (playtime entries, the Riot and Xbox hours and your custom covers, under **Exo account**). The only ID Exo sends for usage is the random install ID of **App data and crash reports**. Your online status, and your current game when your Discord account shares it, go only to Discord (see **Discord**).
- No uploading of your library contents, install folders or store sign-ins. Your playtime, the Riot and Xbox hours and your custom covers go only to your Exo account, as described above.
- No Exo friends list, profiles, handles, badges or chat. The friends, profiles and chat in the Discord room are Discord's own.
- No kernel driver, anti-cheat bypass, or silent approval of Windows security prompts.
- No server anyone else can reach. The OBS browser source for achievement banners (`http://127.0.0.1:9364/achievements`) listens only on this PC's loopback address and answers only requests addressed to it; it serves the banner page and the achievements you unlock while Exo runs, nothing else.
- The clipboard is read only when you open **Activate key**, to spot a game key, and only on this PC. Exo then opens the store's own redeem page (for Epic it copies the key for you to paste); it does not send the key anywhere itself. Exo Capture writes to the clipboard when you snip or press Copy or Send to Discord, and never reads it. In Exo's own Discord client, Copy Image puts the picture on the clipboard and Save Image saves it in your Downloads folder.
